# Student Assistant

## Опис
Student Assistant — навчальний застосунок-планувальник завдань для студентів: додавання, перегляд та відмітка виконання навчальних завдань.

## Архітектура
Кросплатформна, гетерогенна система з кількох незалежних клієнтів (веб, десктоп, нативний C++, аналітика на Python), що обмінюються даними через спільний файл tasks.json.

## Технології
- React — веб-інтерфейс (Модуль 2)
- Electron / NW.js — десктопна обгортка (Модуль 3)
- C++ / Qt — нативний десктопний клієнт (Модуль 4)
- Python / Flet — аналітична панель (Модуль 4)

## Структура репозиторію
- frontend/ — React-фронтенд
- desktop-container/ — Electron/NW.js-контейнер
- cpp-core/ — нативний C++/Qt-клієнт
- python-analytics/ — аналітичний модуль на Python
- data/ — спільний файл обміну даними tasks.json

## Автор
Керкез таня, група КН-5

### Вибір підходу до стилізації
Для проєкту `student-assistant` зручнішим є використання звичайних CSS-класів у поєднанні з умовним рендерингом у JSX. Такий підхід дозволяє повністю відокремити стилі від логіки компонентів, не потребує встановлення додаткових бібліотек і є простішим для підтримки на етапі розробки. Водночас Styled Components добре підходять для великих проєктів із великою кількістю динамічних станів, оскільки виключають конфлікти імен класів.

## Запуск десктопної версії

1. Завантажити збірку **NW.js (SDK)** з офіційного сайту [nwjs.io/downloads](https://nwjs.io/downloads/) для вашої операційної системи.
2. Розпакувати архів у директорію поза межами репозиторію (наприклад, `C:\nwjs` для Windows або `~/nwjs` для macOS).
3. Перейти в теку `frontend/` та виконати збірку проєкту командою `npm run build`.
4. Перейти в теку `frontend/dist/` (`cd dist`) та запустити контейнер командою `C:\nwjs\nw.exe .` (для Windows) або `~/nwjs/nwjs.app/Contents/MacOS/nwjs .` (для macOS).

## Файл даних

Спільний файл даних проєкту розташований за шляхом `data/tasks.json` у корені репозиторію. Якщо під час запуску в контейнері NW.js файл або тека `data` відсутні, застосунок автоматично створює їх з порожнім масивом `[]\n`. Для запису використовується прапорець `wx` (атомарна операція створення лише за умови відсутності файлу), що унеможливлює перезапис існуючих даних при одночасному доступі.

| Сценарій | Очікуваний результат | Фактичний результат |
|----------|----------------------|---------------------|
| А. Файл `data/tasks.json` існує | Напис «Файл даних знайдено» із розміром файлу, вміст не змінюється | Виконано, розмір збігається з оригіналом, `git status` чистий |
| Б. Файл `data/tasks.json` відсутній | Створюється файл із вмістом `[]\n` (3 байти), повторний запуск знаходить його | Виконано, при першому запуску файл створено, при другому знайдено (3 байти) |
| В. Тека `data` відсутня | Автоматично створюється тека `data` і файл `tasks.json` | Виконано (`mkdir` з `recursive: true` створив теку та файл) |
| Г. Запуск у звичайному браузері (`npm run dev`) | Напис «Режим браузера: файл даних недоступний» без помилок у консолі | Виконано, `window.require` відсутній, спрацював статус `unavailable` |

## Формат і запис даних

Спільний файл даних проєкту зберігається у корені репозиторію за шляхом `data/tasks.json` і має структуру JSON-масиву об'єктів із полями `id`, `title`, `completed`, `dueDate` та `priority`. Читання (десеріалізація через `JSON.parse`) і запис (серіалізація через `JSON.stringify`) виконує React-застосунок у контейнері NW.js за допомогою асинхронного модуля Node.js `fs.promises`. Файл записується з відступами у 2 пробіли (`null, 2`) та символом переведення рядка в кінці, щоб він залишався читабельним для людини та коректно відстежувався системою контролю версій Git.
