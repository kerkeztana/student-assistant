# Аналіз технічного завдання проєкту «Student Assistant»

## Функціональні вимоги
* Створення, редагування, перегляд та видалення навчальних завдань (CRUD-операції).
* Відстеження дедлайнів та зміна статусу виконання завдань (виконано / у процесі / прострочено).
* Фільтрація та сортування завдань за предметом, пріоритетом або терміном здачі.
* Формування базової статистики та аналітики навчального навантаження студента.
* Збереження даних у спільному файлі для доступу з різних клієнтських модулів.
*(Доповніть іншими функціями, які вказані у вашому файлі ТЗ)*

## Нефункціональні вимоги
* **Кросплатформність:** коректна робота на операційних системах Windows, Linux та macOS.
* **Швидкодія:** миттєвий відгук інтерфейсу та швидка обробка списку завдань без затримок.
* **Надійність та цілісність даних:** валідація полів під час введення та захист файлу даних від пошкодження.
* **Зручність використання (Usability):** зрозумілий, сучасний та інтуїтивний інтерфейс для користувача.

## Модулі та технології
| Папка модуля | Призначення | Технологічний стек |
| :--- | :--- | :--- |
| `frontend/` | Користувацький вебінтерфейс | HTML, CSS, JavaScript, React |
| `desktop-container/` | Кросплатформна десктопна оболонка | Electron |
| `cpp-core/` | Ядро бізнес-логіки та високопродуктивної обробки | C++ / Qt |
| `python-analytics/` | Модуль аналітики, звітів та візуалізації статистики | Python |
| `data/` | Спільне локальне сховище даних | JSON (`tasks.json`) |

## Формат обміну даними
Взаємодія між усіма модулями системи відбувається через спільний файл `data/tasks.json`. Він містить масив об'єктів завдань, де кожен запис має таку базову структуру:
* `id` — унікальний числовий або рядковий ідентифікатор завдання;
* `title` — назва або короткий опис завдання;
* `subject` — назва навчальної дисципліни;
* `deadline` — дата та час кінцевого терміну здачі (у форматі ISO 8601);
* `priority` — пріоритетність виконання (наприклад, `low`, `medium`, `high`);
* `completed` — логічний прапорець статусу виконання (`true` або `false`).
